# Integrated 2.0.0 融合变更与取舍

日期：2026-10-22（Asia/Shanghai）。基础为此前实现 A，参考本次上传 B：`PrefabToPsd_v1.4.0_SourceFidelity_Unity2018_4_36f1.zip`。本版是独立融合实现，未将存在问题的两套入口并行叠加。安装与命令行用法见 [README](../README.zh-CN.md)，实测结果见 [TestReport.zh-CN.md](TestReport.zh-CN.md)。

## 保留 A 的基础

| 基础能力 | 保留原因 |
| --- | --- |
| Unity 完整子树实际渲染 | Image Fill、UV、旋转、镜像、九宫格、遮罩及效果交给 Unity，而不是再写一套不完整采样器 |
| 浮点黑/白双背景 Alpha 恢复 | 避免透明 RT 读回数据被直接当作 straight RGBA |
| 单次烘焙 CanvasGroup、文件夹 opacity255 | 避免父组和孩子重复乘透明度 |
| PSD merged 白底编码 | 使存储预览与图层数据遵守各自格式约定 |
| 隔离预览场景和源元数据 JSON | 导出布局在副本完成，文字原文与原始变换可检查 |
| 同目录临时文件与原子提交 | 失败或取消不先毁掉上次正确输出 |
| 可取消、CLI、独立格式检查 | 用户可控制长任务，格式结论有独立读取证据 |

## 融入 B 的优点，并修正衔接

| B 的方向 | 融合实现 | 与直接复制 B 的区别 |
| --- | --- | --- |
| 预检树、定位、统计 | `PrefabPsdPreflight` 和窗口树过滤/定位 | 纯读取，不对源对象强制布局重建；明确边界和内存只是估算 |
| 多种生产预设 | 当前外观、美术交付、回导结构、原稿参考 | 预设显式应用；不在执行中暗改用户尺寸、压缩和内存 |
| 图层命名/控件角色 | 有限的容器语义及栅格安全后缀 | 文字保持 `.img`，不伪装 `.txt`；已烘焙切片不追加 `@slice` |
| 空组与 Canvas 信息 | 可保空文件夹和隐藏 `#Canvas`，JSON保存原布局 | 不伪造隐藏 Graphic 启用后的像素；没有可见内容的整个源明确失败 |
| Project 多选批量 | `PrefabPsdBatchService`，GUI/CLI共用 | 使用当前 Options 快照，不重建默认配置；错误聚合、去重、稳定防冲突文件名 |
| 原稿身份恢复 | 已知来源路径、唯一来源ID或精确名字/边界匹配 | 不模糊猜测，不恢复原稿层序覆盖当前排序，恢复 ID 后全树去重 |
| 原稿像素复用 | 严格安全层、边界和逐字节RGBA完全一致才复用 | 不用 MAE 或文字样式近似判断“未修改”；保留字体、对齐、描边和局部像素变化 |
| 分辨率与 ICC 继承 |1005、经核验sRGB的1039、1.0像素比例的1064 | 不盲贴未知/AdobeRGB profile，不用非方形比例改变 Unity 输出显示 |
| 导出后读回 | 默认验证真实临时文件全部承诺内容 | 在原子提交之前验证，失败仍保留旧目标；不将结构自读回称为完整视觉往返 |

## 统一流程

Window 与 CLI 均建立 ExportOptions，预设只改变规定字段。单对象导出取快照；批量取同一快照再复制给每项。Preset、显式参考路径、验证、尺寸、压缩和JSON不会在批量按钮处丢失。

原稿参考只辅助身份和完全相同的图像。身份匹配可恢复 lyid，同时保留当前修改后的像素；像素复用和名称恢复另有更严格条件。当前层序始终保留。来源名称危险或用户已改名时，不强行恢复旧名，JSON仍记录原名。

写文件流程为“构建文档 → 临时写入 → 完整读回校验 → 原子提交 → JSON独立提交”。提交前任一点失败或取消，都不会主动删除旧PSD。提交后没有可取消回调再将成功改记为失败。

## 没有纳入的高风险能力

- B 的实验性 TySh/SoCo 写入未纳入：本版不声称提供 Photoshop 原生可编辑文字或纯色对象。
- 不复制字符矩形占位字形；无法绘制时应有明确失败/提示，而不是用近似字形冒充成功。
- 不采用 CPU 矩形采样器替代 Unity Image 的径向填充、UV、遮罩、PPU和变换。
- 不通过恢复原稿排序或近似文字判定，覆盖用户在 Prefab 中的真实修改。
- 不加入立即回导并声称闭环成功的按钮。结构预设可服务原插件，但完整回导的交互组件、文字引擎与视觉仍需项目验证。
- 不把隐藏节点的启用后外观当成当前快照。隐藏状态、文字和布局留在JSON，隐藏Graphic像素不导出。

## 使用边界没有被“融合”消除

根变换使用指定设计画布归一；复杂跨Canvas三维排序、任意目标依赖Shader、TMP复杂子网格、SRP/LWRP仍未全面认证。大画布和多图层需要较高渲染/内存成本。JSON与PSD不是联合事务，不能将二者当作一次数据库提交。

本版附编译、纯托管和编辑器自测入口。真实程序集编译和文件/策略测试有各自证据，不能替代 Unity GPU 和 Photoshop GUI实机验收；最终状态以测试报告为准。
